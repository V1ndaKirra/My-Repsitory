# Undergrad Defense Focus

本文件定义本科毕设论文的默认写作重心。目标不是把论文写得像研究生学术论文，而是帮助答辩老师快速确认：这个项目是不是你自己做的，你到底做了多少，你是否理解自己的技术选择和实现过程。

## Default Lens

答辩老师通常最关心：

- 你做了哪些真实功能和模块
- 你是否真的写过对应代码与配置
- 你为什么选用当前框架、数据库和实现方案
- 你在开发中遇到了哪些真实问题
- 你有没有独立排查和解决问题的能力

## What To Emphasize

### 1. Workload Evidence

优先把这些内容写清楚：

- 模块划分
- 关键接口
- 数据库表与字段
- 页面与交互流程
- 核心算法或业务规则
- 配置与部署要点

最好在实现章节用 `path:` 引用证据，例如：

```text
path: modules.order.controller
path: data_model.entities.order_info
path: apis.by_module.auth
```

这样后续预检和答辩准备都能回到具体实现。

### 2. Framework Selection Rationale

本科论文里不需要把“技术选型”写成空泛综述，更应该回答：

- 为什么用 Spring Boot 而不是更重或更轻的方案
- 为什么前端选 Vue 3 / Vite
- 为什么数据库用 MySQL
- 为什么认证采用 JWT 或 Session

建议使用句式：

- “本系统选用 X，主要因为……”
- “考虑到项目规模、开发周期与维护成本，采用……”
- “相比 Y，X 更适合本课题的原因是……”

### 3. Development Difficulties And Fixes

这是本科答辩很重要的一块。不要只写“系统顺利完成”，而要写：

- 遇到了什么问题
- 这个问题为什么出现
- 你尝试过哪些方案
- 最后为什么采用现在的方案

常见可写点：

- 权限拦截与接口放行冲突
- 前后端联调时的跨域与 token 失效
- 数据库表关系和级联更新
- 分页、模糊查询、事务一致性
- 性能瓶颈、重复提交、并发冲突
- OCR、图表渲染、依赖安装等工程问题

### 4. Concrete Instead Of Grandiose

本科毕设尽量少写：

- “国内外研究达到空前高度”
- “随着信息化时代的到来”
- “具有重要理论意义和广泛应用前景”

更适合写：

- 当前系统支持哪些角色、流程和业务操作
- 哪些模块是自己独立完成的
- 哪些技术选择是结合项目约束做出的
- 哪些问题是实际开发中遇到并解决的

## Recommended Chapter Intent

### Chapter 3: 需求分析

- 讲清业务对象、角色、核心流程
- 不要堆太多空泛背景

### Chapter 4: 系统设计

- 讲清架构、模块、数据库、接口划分
- 顺手交代技术选型理由

### Chapter 5: 系统实现

- 这是展示“你真的做过”的核心章节
- 多写实现细节、关键逻辑、接口流程、页面交互、代码证据

### Chapter 6: 系统测试与问题处理

- 不只写测试通过
- 要写实际调试、问题定位、修复结果和改进

## Preflight Expectations

对于本科模式，论文至少应该让预检能看见：

- 可追溯的 `path:` 证据
- 技术选型理由
- 至少 1-2 个真实开发难点及解决过程
- 图表与实现内容之间的呼应

如果这些内容缺失，论文即使格式工整，也很难在答辩时体现工作量。
